# Skill 研发协作说明

本文档说明如何在项目研发中结合 `documents` 与 `spreadsheets` 使用 Skill，形成可沉淀、可追踪、可复用的研发资料。

## 使用目标

- 通过 `documents` 沉淀研发文档，统一输出 Markdown 说明。
- 结合 `spreadsheets` 完成项目追踪、Bug 归类和评测数据整理。
- 让问题记录、分析结论和评测结果都能回流到 `doc/` 目录中。

## 分工方式

| Skill | 主要用途 | 常见输出 |
| --- | --- | --- |
| `documents` | 生成和维护研发文档 | 方案说明、会议纪要、问题总结、评测报告 |
| `spreadsheets` | 处理结构化数据 | 项目追踪表、Bug 分类表、评测结果表 |

## 推荐流程

1. 收集原始信息
   - 从 `doc/known-issues.md`、评测记录、项目过程记录中整理输入。
2. 用 `spreadsheets` 先做结构化整理
   - 按模块、严重度、优先级、状态、结论等字段归类。
3. 用 `documents` 输出总结文档
   - 将表格结论整理成 Markdown，补充背景、判断和行动项。
4. 统一放回 `doc/` 目录
   - 方便后续复用、查找和持续更新。

## 适用场景

- 项目追踪
  - 记录任务进度、负责人、截止日期和风险点。
- Bug 归类
  - 按模块、现象、根因和修复状态进行分类。
- 评测数据整理
  - 汇总测试样本、评测结果、覆盖范围和异常项。
- 研发文档沉淀
  - 形成可长期维护的技术说明和过程文档。

## 示例写法

- `通过 documents 沉淀研发文档，结合 spreadsheets 用于项目追踪、Bug 归类和评测数据整理。`
- `先用 spreadsheets 对问题和数据进行分类汇总，再用 documents 生成 Markdown 形式的研发说明。`
- `将评测结果整理到 spreadsheets 中，再输出到 doc 目录下的总结文档。`

## 说明

- `documents` 更适合承载结论、说明和流程。
- `spreadsheets` 更适合承载结构化数据和统计结果。
- 两者配合时，通常是“先表格化，再文档化”。
