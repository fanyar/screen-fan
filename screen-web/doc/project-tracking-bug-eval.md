# 项目追踪、Bug 归类与评测数据整理

本文档基于 `doc/known-issues.md`、`doc/best-practices.md`、`doc/architecture.md` 等已有 Markdown 文档整理，配合 `spreadsheets` 进行结构化记录，再用 `documents` 输出研发说明。

## 使用目标

- 用 `spreadsheets` 对问题和数据进行分类汇总。
- 用 `documents` 将汇总结果整理成 Markdown 说明。
- 让项目追踪、Bug 归类和评测数据都能沉淀到 `doc/` 目录。

## 数据来源

| 来源文档 | 作用 |
| --- | --- |
| `known-issues.md` | 提取已有问题、原因、解决方案 |
| `best-practices.md` | 提取研发规范、通用约束 |
| `architecture.md` | 提取模块结构、路由、状态模块 |
| `music-todo.md` | 提取待办项和状态追踪方式 |

## 4. 推荐工作流

1. 先从现有 Markdown 文档中提取条目。
2. 用 `spreadsheets` 按模块、状态、严重度、场景分类。
3. 汇总后输出到 `documents` 生成 Markdown 说明。
4. 最终统一放回 `doc/` 目录，保持持续更新。

## 5. 适用写法

- `通过 spreadsheets 对项目任务、Bug 和评测数据进行分类汇总，再用 documents 生成 Markdown 形式的研发说明。`
- `结合 known-issues.md、best-practices.md 等文档，整理项目追踪、问题归类和评测记录。`
- `将问题和评测样本结构化到表格中，最终沉淀为可维护的 Markdown 文档。`

## 6. 说明

- `spreadsheets` 适合做分类、统计和汇总。
- `documents` 适合做结论、说明和过程沉淀。
- 两者搭配时，通常先整理表格，再生成文档。
